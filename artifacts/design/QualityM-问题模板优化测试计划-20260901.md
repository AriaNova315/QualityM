## 1. 测试目标

证明问题模板优化不会产生模拟审核事实，不会因页面、API 或 Excel 入口不同而违反星标和严重程度规则，不会覆盖并发修改，也不会把待确认建议值误计为正式关闭事实。

测试不得写入正式 `qualitym.db`、`generated/` 或 `temp/` 权威样例。所有数据库和输出文件使用 pytest 临时目录或显式隔离目录。

## 3. 领域规则测试

新增 `tests/test_issue_template_policy.py`，采用表驱动参数化：

| 场景 | 预期 |
|---|---|
| 星标 + 严重 | 通过 |
| 星标 + 一般/轻微 | `ISSUE_SEVERITY_STARRED_REQUIRED` |
| 非星标 + 轻微/一般 | 通过 |
| 非星标 + 严重 | `ISSUE_SEVERITY_NONSTARRED_INVALID` |
| 启用数从 3 增至 4 | 通过 |
| 启用数从 4 增至 5 | `ISSUE_TEMPLATE_ENABLED_LIMIT` |
| 存量 5 条，停用一条 | 通过并降为 4 |
| 存量 5 条，修改标题 | 通过并保留待整理警告 |
| 存量 5 条，新增/复制/重启用 | 阻止 |
| 启用数降为 0 | 允许并返回 `ISSUE_TEMPLATE_COVERAGE_EMPTY` warning |
| 不符合且无实际问题 | 阻止 |
| 确认关闭缺实际整改措施或日期/结论 | `ISSUE_CLOSE_CONFIRMATION_INCOMPLETE` |

断言稳定诊断代码、严重度和关联实体，不断言完整中文提示。

## 4. 迁移与仓储测试

在 `tests/test_database.py` 和新增仓储测试中覆盖：

- 空数据库执行 001～007。
- 006 数据库升级至 007 后，既有模板修订号为 1。
- 旧审核规则版本为 1；新建审核显式为 2。
- 旧审核 `revision > 1` 或 confirmed 被视为已编辑。
- 网页编辑、Excel 提交、种子升级、内置恢复、复制、启停和保存为模板均递增对应整数修订号。
- 无实际变化不递增修订号。
- 两个连接使用相同旧修订号修改同一问题，只有一个成功。
- 任意批次中间异常后数据、修订号和预览状态保持一致。
- `PRAGMA foreign_key_check` 无结果。

## 5. 审核工作流测试

扩展 `tests/test_audit_workflow.py`：

- 新审核的每个 `conclusion` 均为 `NULL`，`nonconformities` 为 0。
- 候选问题模板全部冻结，但没有默认标志驱动的自动问题。
- 一次选择 2～4 个候选模板生成相同数量的独立实际问题。
- 重复候选 ID 只生成一次。
- 自定义问题不消耗模板库 4 条上限。
- 星标项通过 API 发送轻微或一般被拒绝。
- 非星标项通过 API 发送严重被拒绝。
- 保存自定义问题为模板需要显式调用；保存前后当前实际问题字段不变。
- 模板已达 4 条或处于存量超限时，保存为模板被拒绝。
- 候选问题的建议整改、实际日期和验证结论初始标为待确认。
- 未确认问题不计入关闭统计，导出快照不把建议日期当正式事实。
- 确认关闭缺任一必填事实时失败；完整时成功并清除待确认标志。
- 所有人工写操作同时置 `user_edited=1` 并递增审核修订号。
- 已确认和历史审核快照不受全局模板修改影响。

## 6. 简单 Excel 单元与工作簿测试

新增 `tests/test_simple_issue_template.py`：

### 6.1 结构

- 可见工作表仅显示六个业务字段。
- `_row_token` 列存在、隐藏且锁定。
- 系统映射表为 `veryHidden`，工作簿结构保护已开启。
- 检查项、严重程度和状态存在正确数据验证。
- 星标显示为 `5*`，不会成为 `5**`。
- 以 `= + - @` 开头的标题、描述和建议按文本写入，不形成公式。

### 6.2 解析与映射

- 已有行保持令牌、稳定键和修订号对应关系。
- 新增空令牌行按检查项下拉值映射，生成新增差异。
- 排序和插行后身份仍按令牌关联，不按行号关联。
- 复制已有行导致重复令牌，所有冲突行号均可见。
- 修改、显式停用正确识别；删除或遗漏行不产生停用差异。
- 不存在、重复或过期的检查项映射阻止提交。
- 隐藏表被篡改、删除或改为错误格式时明确失败。
- 工作簿格式版本不受支持时明确失败。

### 6.3 容量和边界

- 10,000 行成功预览；10,001 行拒绝。
- 25 MB 边界沿用安全上传测试。
- 标题 200 字符通过、201 字符拒绝。
- 描述和整改建议 4,000 字符通过、4,001 字符拒绝。
- 空白尾行不计入有效行数。
- Unicode、超长中文、换行和特殊符号 round-trip 不丢失。

## 7. Excel 导入服务集成测试

扩展或替换 `tests/test_template_library.py`：

- 普通导出返回简单模板；高级导出仍能生成 28 列备份。
- 新增、修改、显式停用在预览中分类正确。
- 预览不写模板业务表。
- 提交后新增问题获得服务器生成的稳定键、修订号和末尾顺序。
- 删除 Excel 行后提交，数据库原问题保持启用。
- 预览后网页修改同一问题，提交返回逐行并发冲突。
- 预览后修改其他模板导致整库基线变化，提交返回陈旧预览。
- 重复提交、过期令牌、伪造令牌均失败且不产生部分写入。
- 星标冲突、非星标严重、启用数超过 4 均在预览中定位检查项和 Excel 行。
- 存量超过 4 条可显式停用，不能新增、复制或重新启用。
- 同一批次中多行共同使数量达到 4 时通过，达到 5 时整批失败。
- 导入算法使用固定批次查询；测试通过查询计数防止逐行 SQL 回归。

## 8. 草稿刷新与重建测试

新增 `tests/test_audit_refresh.py`：

- 新版未编辑草稿可以预览并刷新候选快照，结论和实际问题保持不变。
- 只打开页面不影响刷新资格。
- 修改审核人、结论或任一问题后，刷新资格立即失效。
- 已确认审核不可刷新。
- 旧版 `draft + revision=1` 预览显示将清除的结论和问题数量。
- 旧版重建后审核 ID、序号不变，全部结论为空、问题为 0、规则版本为 2。
- 旧版 `revision>1`、confirmed 或 `user_edited=1` 不可重建。
- 预览后审核修订号变化、模板基线变化或令牌过期时提交失败。
- 注入删除或插入异常，确认整个子快照和审核元数据回滚。
- 重建前已生成的 Excel artifact 文件保持原样，后续新导出读取新快照。

在开放旧版重建前，建立“旧人工写路径修订号矩阵”，逐一调用全部历史路由并证明每条路径从 revision 1 变为 2。只要发现一个遗漏，重建接口必须保持关闭。

## 9. 页面与浏览器 QA

更新静态契约测试并执行真实浏览器：

1. 导入项目并打开新审核，确认所有项显示未检查且无自动问题。
2. 星标序号显示 `*`，严重程度固定为严重且不可选择其他值。
3. 非星标项只显示轻微和一般。
4. 不符合项一次选择两个模板，保存后出现两张独立问题卡。
5. 创建自定义问题，确认不会自动进入模板库；显式保存为模板后才出现。
6. 未确认建议字段具有清楚的待确认标识；确认关闭缺字段时显示稳定错误。
7. 模板页导出简单 Excel、上传修改文件、查看差异并确认提交。
8. 两个标签页同时编辑同一问题，后提交者收到冲突提示并可刷新。
9. 0 条模板项显示覆盖警告；存量超限项显示待整理并禁用新增类操作。
10. 新版草稿刷新和旧版草稿重建均先展示摘要和确认步骤。

同时检查桌面与窄屏布局、键盘可达性、未保存提醒、重复点击去重和控制台错误。

## 10. Microsoft Excel 代表性冒烟

使用隔离数据库导出的简单问题模板：

1. 在 Microsoft Excel 打开文件，确认无修复提示。
2. 确认用户只看到“问题模板”业务表，六列标题和中文样式正常。
3. 验证检查项、严重程度和状态下拉可用。
4. 在中间插入新行并选择检查项，填写问题后保存。
5. 修改一条已有问题，明确停用另一条；排序整表后再次保存。
6. 上传保存后的文件，确认新增、修改、停用分类正确，排序没有改变身份。
7. 提交并再次导出，确认新增问题获得正式令牌且全部数据一致。

实机检查不把工作表保护当安全证明；篡改和冲突仍由服务端自动化测试负责。

## 11. 内容试点验收

生成任务书 16 项内容验收表，逐项记录：

- 带星序号和检查项原文；
- 1～4 条问题标题、描述、整改建议、严重程度；
- 每条问题对应的具体检查要求；
- 合并或删除近义问题的理由；
- 用户验收结论。

自动检查数量、严重程度、必填字段和规范化后的同项重复；跨项相似只生成审查报告，不自动删除。最终“贴切性”必须由用户业务验收确认。

