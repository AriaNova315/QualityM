# QualityM 问题模板优化工程实施计划

生成日期：2026-09-01  
状态：ENG REVIEWED  
业务依据：`artifacts/design/QualityM-问题模板优化设计-20260901.md`  
范围：工程实施方案，不包含本轮代码修改

## 1. 结论

保留已批准业务范围，按三个可独立验收的里程碑顺序实施：

1. 审核真实性与问题录入闭环；
2. 简单问题模板 Excel 与模板库治理；
3. 草稿刷新/重建、任务书 16 项内容试点和最终验收。

不得把三个里程碑合并成一次不可分割的大改动。每个里程碑必须完成代码、自动化测试、可视或文件产物、文档同步和风险汇报后，才能进入下一里程碑。

## 2. 已确认的工程决策

| 编号 | 决策 |
|---|---|
| D1 | 完整范围分三个里程碑实施，不削减业务目标。 |
| D2 | `checklist_items` 和 `issue_templates` 使用独立、单调递增的整数修订号进行并发控制；现有字符串版本继续表示内容版本。 |
| D3 | `audit_instances` 增加生成规则版本和人工编辑标志；旧草稿重建不得只根据文案猜测。 |
| D4 | 星标、严重程度、模板数量和关闭确认规则集中在纯 Python `domain` 模块，所有写入口共用。 |
| D5 | 符合资格的未编辑草稿在原审核实例内经预览后原子刷新或重建，保留审核 ID 和序号。 |
| D6 | 模板功能按业务能力拆分，并建立模板仓储；不继续扩张现有巨型模板服务。 |
| D7 | 验收采用四层自动化、浏览器 QA 和真实 Microsoft Excel 代表性冒烟。 |
| D8 | 简单 Excel 使用有界同步预览：文件不超过 25 MB，有效问题行不超过 10,000。 |

## 3. 已有能力与复用点

- SQLite 连接工厂已经统一启用外键和 `busy_timeout`，写事务使用 `BEGIN IMMEDIATE`。
- 审核编辑已有 `audit_instances.revision` 乐观锁，结论接口已经接受多个 `issue_template_ids`。
- 审核实例已冻结检查单、检查项和候选问题模板快照，模板更新不会直接改写既有审核。
- 模板导入已有一次性预览令牌、过期时间、模板库基线摘要和单事务提交机制。
- 文件上传已有 OOXML、安全大小和压缩比校验。
- Excel builder 已有公式注入防护、openpyxl 重开验证和真实 Excel 验收脚本基础。
- 导出服务先构造不可变快照，再交给 Excel builder；该边界保持不变。

现有能力应迁移或复用，不得并行保留两套相互独立的并发、预览或错误码机制。

## 5. 数据模型与迁移

新增连续编号迁移 `007_problem_template_workflow.sql`，不得修改既有迁移。

### 5.1 模板并发字段

- `checklist_items.revision INTEGER NOT NULL DEFAULT 1 CHECK (revision > 0)`
- `issue_templates.revision INTEGER NOT NULL DEFAULT 1 CHECK (revision > 0)`

网页编辑、Excel 提交、种子升级、恢复内置内容、复制、启停和“保存为问题模板”等所有有效变更，都必须在同一写事务中递增对应修订号。无实际变化不得递增。

字符串 `version`/`builtin_version` 保留，用于内容发布和快照展示，不再作为并发锁的唯一依据。

### 5.2 审核生成与人工编辑字段

- `audit_instances.snapshot_schema_version INTEGER NOT NULL DEFAULT 1`
- `audit_instances.user_edited INTEGER NOT NULL DEFAULT 0 CHECK (user_edited IN (0, 1))`

新规则创建的审核显式写入 `snapshot_schema_version = 2`、`user_edited = 0`。任何审核人、状态、检查结论、问题新增/修改/删除或其他业务字段保存，都必须在原事务中写入 `user_edited = 1` 并递增审核修订号；只读打开页面不改变它。

旧记录迁移为规则版本 1。`revision > 1` 或已确认的旧记录直接视为已编辑。`revision = 1` 的旧草稿只有在“全部旧人工保存路径均递增修订号”的专项测试通过后，才可开放重建。

### 5.3 刷新/重建预览

新增独立的审核刷新预览表，至少保存：令牌哈希、审核 ID、操作类型、审核修订号、模板库基线、变化摘要、状态、过期时间和创建时间。令牌一次性使用，不与模板 Excel 导入令牌混用。

## 6. 领域规则契约

新增纯领域模块，对外返回稳定诊断代码和结构化结果，不依赖完整中文提示文案。

核心规则：

- 星标检查项的问题模板和实际问题只能为“严重”。
- 非星标检查项只能为“轻微”或“一般”。
- 启用问题模板允许为 0～4 条；0 条返回覆盖警告，不阻止审核自定义问题。
- 存量启用数超过 4 条时允许查看、修改内容和停用；阻止新增、复制、重新启用或保存自定义问题为模板。
- 停用历史不计入 4 条上限；审核实例中的自定义问题不受该上限约束。
- 不符合项保存时至少有一条实际问题。
- 确认关闭时，实际整改措施、实际关闭日期、验证日期和验证结论必须完整。
- 取消默认问题业务概念，任何流程不得自动选择候选问题。

建议诊断代码包括：

- `ISSUE_SEVERITY_STARRED_REQUIRED`
- `ISSUE_SEVERITY_NONSTARRED_INVALID`
- `ISSUE_TEMPLATE_ENABLED_LIMIT`
- `ISSUE_TEMPLATE_COVERAGE_EMPTY`
- `ISSUE_TEMPLATE_LEGACY_OVER_LIMIT`
- `ISSUE_CLOSE_CONFIRMATION_INCOMPLETE`

## 7. 里程碑一：审核真实性与问题录入闭环

### 7.1 实现任务

1. 执行 007 迁移并补充迁移、回滚和外键检查测试。
2. 删除审核创建链路对 `issue_generation.suggest_nonconforming_items` 的调用；新检查项结论写为 `NULL`，不创建问题事实。
3. 快照冻结全部启用候选问题，但不读取 `is_default` 决定候选或顺序；迁移可清零默认标志，旧字段暂留兼容。
4. 接入领域规则，服务端强制星标严重程度约束；前端下拉选项只显示允许值。
5. 页面把单选候选问题改为多选；提交时一次创建多条独立问题，重复候选 ID 去重。
6. 支持当前审核的自定义问题；星标项严重程度锁定为严重，非星标项只显示轻微、一般。
7. 新增“保存为问题模板”独立操作。用户必须确认并可调整可复用标题、描述和整改建议；服务端生成稳定键，不反向修改当前或历史问题。
8. 选择模板后预填计划日期和整改/验证建议值，但统一标记 `suggested_closed = 1`；确认前不计入关闭统计，也不作为正式关闭事实导出。
9. 确认关闭校验增加实际整改措施；确认成功后清除待确认标志。
10. 审核页、模板页和所有审核导出在序号后统一显示 `*`，避免重复追加。

### 7.2 兼容处理

- 保留现有审核和问题 API 地址，必要时扩展请求/响应字段。
- 旧审核快照继续可读，不因取消默认问题字段而加载失败。
- `app/domain/issue_generation.py` 若无其他调用则删除；若测试工具仍使用，先迁移调用再删除。

### 7.3 验收门禁

- 新建审核所有检查项均为未检查，问题数为 0。
- 同一不符合项可一次选择多个模板，也可创建多个自定义问题。
- 页面、API 直调和导出均不能绕过星标严重程度规则。
- 未确认建议值在统计和导出中不形成关闭事实。
- 全量 pytest 通过，审核浏览器闭环通过。

## 8. 里程碑二：简单 Excel 与模板库治理

### 8.1 模块拆分

- 将现有 `template_service.py` 拆为问题模板服务、批量导入服务和模板仓储。
- 保留兼容导入层或逐步调整路由引用，避免同一次提交中无关 API 改名。
- 现有 28 列 builder/reader 保留为高级备份能力，不作为普通按钮入口。

### 8.2 简单工作簿结构

可见工作表名为“问题模板”，字段固定为：

1. 检查项
2. 问题标题
3. 问题描述
4. 整改建议
5. 严重程度
6. 状态

第 7 列 `_row_token` 隐藏且锁定。隐藏系统表使用 `veryHidden`，保存：

- 可选择检查项的唯一显示值、层级稳定键、检查项修订号和星标；
- 已有问题的随机行令牌、问题稳定键、问题修订号及所属检查项；
- 导出格式版本。

工作簿保护只用于防误操作，不被视为安全边界。导入端必须把全部隐藏内容视为不可信输入，并重新根据数据库校验归属、修订号、星标和状态。

新增行的 `_row_token` 为空，系统按“检查项”下拉值映射并在提交时生成问题稳定键；下次导出才包含正式令牌。复制已有行造成令牌重复时阻止预览提交。

### 8.3 增量导入语义

- 有身份且内容变化：修改。
- 无身份且内容完整：新增。
- 状态明确为停用：停用。
- 文件中遗漏或删除的数据库记录：不变。
- 已有问题保持原顺序；新增问题追加到所属检查项末尾。
- 预览展示新增、修改、停用、重复、未匹配、过期映射、规则冲突和警告。
- 提交重新校验预览令牌、整个模板库基线、逐项修订号和全部领域规则；任一失败则整体回滚。

### 8.4 容量边界

- 最大文件：25 MB。
- 最大有效问题行：10,000。
- 问题标题：1～200 字符。
- 问题描述和整改建议：各 1～4,000 字符。
- 解析只进行一次；数据库映射一次批量预取；校验按哈希字典实现 O(n)，禁止逐行数据库查询。

### 8.5 页面入口

- 原“导出 Excel”按钮直接下载简单问题模板。
- 普通导入框只接受简单问题模板。
- 完整 28 列文件可放在“高级备份”入口，不与普通导入混用。
- 模板树显示每项启用数量、0 条覆盖警告和存量超限“待整理”警告。

### 8.6 验收门禁

- 用户无需查看或维护内部稳定键、版本和层级字段。
- 新增行无需编辑隐藏表即可正确归类。
- 删除行不改变数据库，显式停用才生效。
- 网页和 Excel 并发修改均能返回稳定冲突诊断，不覆盖较新数据。
- 1,288 行当前库及 10,000 行边界夹具在目标时间内完成预览。
- openpyxl 重开、浏览器流程和 Microsoft Excel 代表性冒烟通过。

## 9. 里程碑三：草稿刷新、旧版重建与内容试点

### 9.1 新版未编辑草稿刷新

- 仅 `draft + snapshot_schema_version=2 + user_edited=0` 可刷新候选模板。
- 预览列出新增、修改、停用候选数量；提交只替换候选快照，不改变检查结论或实际问题。

### 9.2 旧版草稿重建

- 仅 `draft + snapshot_schema_version=1 + revision=1` 且专项修订号审计通过的记录可重建。
- 预览明确显示将清除的结论数和问题数。
- 提交在原审核实例内删除旧子快照，按新版规则重建全未检查状态，更新规则版本并递增修订号。
- 已确认、人工编辑、预览过期、审核修订号变化或模板基线变化均返回 409，数据库不发生变化。

### 9.3 软件研制任务书 16 项内容试点

- 逐项形成 1～4 条贴切问题，通常 2～4 条，不为凑数制造同义改写。
- 每条记录包含检查项映射、问题标题、描述、整改建议、严重程度和映射理由。
- 星标项全部严重；非星标项只使用轻微或一般。
- 先生成内容验收表，再写入版本化种子；用户提供的历史问题用于校准粒度、去重和归类。
- 在用户完成 16 项业务确认前，不扩展重做其余 24 类检查单内容。

### 9.4 验收门禁

- 新版未编辑草稿刷新不改变结论和实际问题。
- 旧版初始草稿可经预览重建；任何可能含人工事实的审核不可重建。
- 任务书 16 项全部有 1～4 条经业务确认的问题，无明显同义重复。
- 审核页面、简单 Excel、审核导出和内容验收表中的星号与严重程度一致。
- 全量回归、浏览器 QA、真实 Excel 冒烟和业务抽查全部通过。


## 11. 失败模式与处理

| 失败模式 | 处理 |
|---|---|
| 隐藏表或令牌被修改 | 视为不可信输入；预览返回映射冲突，不猜测、不提交。 |
| 复制已有行产生重复令牌 | 定位所有重复 Excel 行，作为 blocker。 |
| Excel 删除或漏选行 | 数据库记录保持不变。 |
| 星标与严重程度冲突 | 页面限制并由领域规则再次阻止 API/Excel 提交。 |
| 启用数超过 4 | 存量显示待整理；新增、复制、重启用和保存为模板被阻止。 |
| 预览后网页修改模板 | 整库基线或逐行修订号冲突，提交返回 409。 |
| 提交中任一行失败 | 整个 `BEGIN IMMEDIATE` 事务回滚，预览令牌保持可诊断状态。 |
| 旧草稿可能含人工事实 | 不开放重建；要求保留原记录或重新创建审核。 |
| 待确认建议值被误作事实 | 统计和导出按 `confirmed` 判定，未确认字段标记为待确认。 |
| 内容试点缺少历史输入 | 可完成能力开发和初稿，但不得宣告 16 项内容业务验收完成。 |

## 12. 明确不在范围内

- 不自动读取被审核文档并推断符合性或问题。
- 不保留建议关注项、默认问题或自动选中候选问题。
- 不增加“历史来源备注”。
- 不允许通过 Excel 修改检查单层级、星标、检查项正文或显示顺序。
- 不通过删除 Excel 行隐式停用问题。
- 不使用 VBA、宏或公式回写内部身份。
- 不实现十万行后台导入任务。
- 不一次重做全部 361 个检查项；首批内容仅为任务书 16 项。
- 不修改既有已确认或已编辑审核事实。
- 不修改或覆盖 `temp/` 权威样例。

## 14. 顺序与可并行工作

主路径严格顺序：

```text
领域规则/迁移
      ↓
里程碑一审核闭环
      ↓
里程碑二简单 Excel
      ↓
里程碑三刷新重建与内容试点
      ↓
全量回归和最终验收
```

可并行准备但不能越过门禁的工作：

- 任务书 16 项内容初稿可与里程碑一开发并行整理；写入种子必须等规则契约稳定。
- 简单 Excel 的视觉样式可与导入服务测试夹具准备并行；导入提交必须等模板仓储和修订号完成。
- 浏览器脚本和 Microsoft Excel 冒烟脚本可提前准备；最终执行必须使用完成后的真实构建。

## 15. 完成定义

只有同时满足以下条件，问题模板优化才可标记完成：

1. 三个里程碑分别通过验收门禁；
