# QualityM 问题模板优化设计

生成日期：2026-09-01  
状态：APPROVED  
范围：业务设计讨论，不包含代码实施

## 1. 问题陈述

当前问题模板由少量通用问题族按检查项关键词批量生成。不同检查项可能得到相同的默认标题、描述和整改建议，无法准确反映具体检查要求。审核实例创建时还会通过确定性哈希预填 0～2 个“不符合”项，并把其他项预填为“符合”；这些结论并非来自被审核文档或审核人的实际判断，不适合作为正式质量事实。

## 2. 已确认的业务原则

1. 正式审核实例的所有检查项初始为“未检查”。
2. 不生成“不符合”问题，不生成“符合”结论，也不保留“建议关注项”。
3. 审核人选择“不符合”后，必须从问题模板中选择一条或多条问题，或创建自定义问题。
4. 同一检查项允许关联多个问题，每个问题独立整改、验证和关闭。
5. 自定义问题可由用户主动执行“保存为问题模板”，但不得自动沉淀到全局模板库。
6. 保存为模板前，应把项目特定内容整理为可复用的问题标题、描述和整改建议。
7. 取消“默认问题”概念，不自动选中任何候选问题；候选问题按模板库中保存的顺序显示。

## 3. 星标与严重程度

1. 审核页面、模板维护页面和导出文件均在检查项序号后显示星号，例如 `5*`。
2. 星标检查项下的所有问题固定为“严重”，用户不可修改。
3. 非星标检查项的问题只允许“轻微”或“一般”，不允许“严重”。
4. 上述规则同时约束问题模板和审核实例中的实际问题。
5. Excel 导入发现严重程度与星标规则冲突时应阻止提交，并给出检查项和行号；不得静默接受错误值。

## 4. 初始问题模板的数量与质量

数量规则分为两层，不得混为数据库中的同一个硬约束：

- 初始内容交付验收：每个检查项至少有 1 条贴切的问题模板；
- 日常运行维护：允许用户把某检查项的全部问题模板停用，但显示覆盖警告。

1. 初始模板库中的每个检查项有 1～4 条启用的问题模板。
2. 每个检查项通常配置 2～4 条启用的问题模板，任何检查项不得同时启用超过 4 条；已停用的历史模板不计入上限。
3. 数量由检查项中的独立失效模式决定，不按固定数量机械生成。
4. 两条问题如果缺陷表现、整改措施和关闭证据基本相同，应合并。
5. 不得为满足数量要求增加同义改写或不指向具体检查要求的泛化问题。
6. 运行时允许用户将某检查项的全部模板停用，但模板库应显示覆盖警告；正式审核仍可创建自定义问题。
7. 新增、重新启用或“保存为问题模板”会使启用数超过 4 条时，阻止操作并提示先停用或合并已有模板；审核实例中的自定义问题不受模板数量上限影响。

初始模板验收应覆盖：

- 每个检查项经过业务审查；
- 每条问题能映射到检查项中的具体要求；
- 同一检查项内不存在同义问题；
- 跨检查项重复问题形成检查报告并人工确认；
- 每条问题包含明确标题、问题描述、整改建议和符合星标规则的严重程度。

## 5. 简单问题模板 Excel

模板库页面的“导出 Excel”按钮改为导出面向用户的简单问题模板，而不是当前 28 列完整层级文件。

### 5.1 用户可见主表

| 字段 | 规则 |
|---|---|
| 检查项 | 下拉选择，显示检查单、分组（如有）、带星序号和检查项摘要 |
| 问题标题 | 必填，可编辑 |
| 问题描述 | 必填，可编辑 |
| 整改建议 | 必填，可编辑 |
| 严重程度 | 星标项固定严重；非星标项选择轻微或一般 |
| 状态 | 启用或停用 |

不保存、导入或展示“历史来源备注”。

### 5.2 隐藏系统映射表

隐藏表保存检查项显示值与稳定键之间的映射，以及已有问题的内部身份。主表同时包含用户不可见、受保护的 `_row_token` 隐藏列；隐藏映射表通过该 token 关联问题身份和检查项身份，不得按可能被排序改变的 Excel 行号建立关联。

用户新增问题行时无需同步修改隐藏表：新行的 `_row_token` 和问题身份为空，导入时系统根据用户选择的检查项完成映射并生成新的 token、问题稳定键和版本信息。下次导出时，新问题包含正式内部身份。复制已有行造成 token 重复时，预览报告冲突并阻止提交。

不使用 VBA、宏或依赖 Excel 公式回写内部身份。

### 5.3 导入语义

1. 修改带内部身份的已有行表示修改问题模板。
2. 新增且无问题身份的行表示新增问题模板。
3. 只有把“状态”明确改为“停用”才停用问题。
4. Excel 中删除、筛选遗漏或未包含的行不改变数据库现状。
5. 问题模板只停用，不物理删除，已有审核快照永久保留。
6. 复制已有行导致内部身份重复时，预览必须报冲突并阻止提交。
7. 检查项的层级、稳定键、启用状态、星标或显示内容在文件导出后发生变化时，预览应判定对应映射过期；不得仅按显示名称猜测匹配。
8. 导入必须先展示新增、修改、停用、重复、未匹配和规则冲突，再由用户确认提交。
9. 隐藏映射保存导出时的检查项版本和问题版本；网页或另一份 Excel 已修改同一记录时，预览报告并发冲突，不得覆盖较新内容。
10. 预览绑定模板库基线；预览后模板库再次变化时，确认提交必须失败并要求重新预览。提交采用单一原子事务，不产生部分更新。
11. 第一阶段不通过 Excel 调整已有问题的显示顺序：已有问题保留原顺序，新增问题追加到该检查项末尾。后续如需排序，另行设计明确的业务字段，不依赖工作表全局排序结果。

完整 28 列模板库导出仍可保留为系统备份或高级维护能力，但不作为普通用户的日常入口。

网页中的单条问题新增、编辑、复制和停用能力继续保留，适合少量维护；网页与 Excel 使用相同的星标、严重程度、数量上限、版本冲突和停用规则。

存量模板中的“默认问题”标志在迁移后不再具有业务意义：页面、审核生成、排序和导出均不得读取该标志，也不得据此自动选择问题。迁移可以清除该标志；如为兼容旧数据库而暂时保留字段，其值也只能作为无效历史数据。

## 6. 审核问题录入流程

1. 审核实例创建后，所有检查项均为“未检查”。
2. 审核人选择“符合”“不符合”或“不适用”。
3. 选择“不符合”后，页面展示该检查项的全部启用问题模板，不预选任何模板。
4. 审核人可以一次选择多个模板，也可以新增自定义问题。
5. 每条问题形成独立记录，分别维护责任人、整改、日期、验证和关闭状态。
6. 不符合项至少存在一条实际问题后才能保存。
7. 自定义问题可通过独立操作保存为模板；保存模板不会反向改变当前问题或历史问题。

## 7. 整改和验证建议值

选择问题模板后可以预填待确认建议值，以减少重复输入，但不得把建议值当作已发生事实：

- 计划关闭日期按现有规则计算；
- 模板中的整改建议作为参考内容；
- 拟采取的实际整改措施可以用整改建议初始化为草稿；
- 建议实际关闭日期和建议验证日期可默认等于计划关闭日期；
- 建议验证结论可预填“已整改并验证通过”；
- 所有上述内容在关闭确认前明确标记为“待确认”。

未勾选“关闭已确认”前：

- 不计入已关闭问题统计；
- 导出中不得作为正式关闭事实；
- 页面和导出均应清楚显示“待确认”；
- 确认关闭时校验实际整改措施、实际关闭日期、验证日期和验证结论完整。

“整改建议”与“实际整改措施”是两个不同概念，导出中不得混用。

## 8. 模板更新对已有审核的影响

1. 已确认审核永不随模板变化。
2. 已编辑草稿保留原快照。
3. 完全未编辑的草稿允许用户主动执行“刷新问题模板”。新版审核应保存明确的 `user_edited` 事实；保存审核人、结论、问题或其他业务字段均算作已编辑，仅打开页面不算。
4. 刷新前展示变化摘要并要求确认。
5. 刷新只替换候选问题模板，不填写结论、不创建问题。
6. 新建审核实例直接使用当前问题模板库。

### 8.1 旧版自动生成草稿的过渡规则

旧版审核创建时已经带有哈希生成的结论和问题，因此不能只刷新候选模板。过渡期采用以下规则：

- 状态为草稿且修订号仍为创建时初始值的旧版审核，可由用户主动执行“按新版规则重建”；
- 重建会清除系统生成的问题，把全部检查项重置为“未检查”，并加载当前候选问题模板；
- 重建前展示将被清除的结论和问题数量，并要求确认；
- 修订号已变化或已经确认的旧版审核一律视为可能包含人工事实，不允许自动重建；
- 不通过内容相似度或问题文案猜测记录是否由人工编辑。

实施前必须验证旧版所有人工保存路径都会推进审核修订号。只要发现一种人工编辑不会推进修订号，就不得仅以修订号判断可重建性；应先补充可靠的人工编辑标记，再开放旧版草稿重建。

## 9. 分阶段落地范围

第一阶段拆为“全局能力改造”和“内容试点”，避免把两类范围混淆。

### 9.1 全局能力改造

- 所有新审核实例使用“未检查”初态，不再生成模拟事实；
- 支持多问题、自定义问题、保存为模板和待确认建议值；
- 页面、API、Excel 导入和审核导出统一执行星标与严重程度规则；
- “导出 Excel”导出全量简单问题模板，包含当前全部检查单的问题内容；
- 其余 24 类检查单在内容尚未重做前暂时保留现有问题模板，但不再被自动生成到审核记录中。

其余 24 类检查单中已经存在超过 4 条启用模板的检查项采用兼容过渡：不自动决定停用哪一条，保留现状并显示“待整理”警告；在人工整理到 4 条以内前，禁止新增、重新启用或保存自定义问题为该检查项的模板。

### 9.2 内容试点

第一阶段只重做“软件研制任务书检查单”的问题内容：

1. 覆盖全部 16 个检查项；
2. 每项 1～4 条贴切问题模板；
3. 使用全局能力完成任务书内容的导出、修改、新增、停用、审核录入和刷新验收；
4. 用用户后续提供的历史问题验证问题粒度、措辞、去重和归类规则；
5. 用户验收后，再按相同标准扩展到其余 24 类检查单。

任务书 16 项的具体问题标题、描述、整改建议、严重程度和映射理由作为独立的“内容验收表”交付；本设计稿只定义生成与验收规则，不以通用规则代替逐项业务内容。

## 10. 不采用的方案

- 不继续用确定性哈希生成模拟审核结论或建议关注项。
- 不要求用户维护 28 列内部模板结构。
- 不通过删除 Excel 行隐式停用问题。
- 不保留历史来源备注。
- 不允许星标项出现轻微或一般问题。
- 不允许非星标项出现严重问题。
- 不保留默认问题或自动选中候选问题。
- 不一次性重做全部 361 个检查项后再进行业务验证。

## 11. 第一阶段验收标准

1. 任务书检查单 16 项全部显示正确序号和星号。
2. 每项有 1～4 条经过业务审查的问题模板，且无明显同义重复。
3. 新审核实例全部为“未检查”，没有自动结论或问题。
4. 一个不符合项可以一次生成多个独立问题。
5. 自定义问题可以用于当前审核，并能经用户确认保存为模板。
6. 简单 Excel 不展示内部版本、稳定键和层级控制字段。
7. 新增行无需修改隐藏表即可正确归入目标检查项。
8. 删除 Excel 行不影响数据库；显式停用才生效。
9. 星标和严重程度规则在页面、API、导入校验和导出中一致。
10. 建议整改和验证值在关闭确认前始终标为待确认，不计入已关闭统计。
11. 已确认或已编辑审核不被模板刷新改变。
12. 旧版初始修订草稿可经确认重建为全未检查状态；旧版已编辑或已确认记录不能重建。
13. Excel 行身份不依赖行号，排序、插行和复制不会造成静默错配。
14. Excel 和网页的并发修改能在预览或提交阶段被识别，较新内容不会被覆盖。
15. 模板数量上限只计算启用模板；停用历史不占上限，审核实例自定义问题不受上限影响。
16. 旧版所有人工保存路径均经测试确认会推进修订号；否则旧版草稿重建功能不得开放。
17. 存量默认标志不再影响页面、排序、审核生成或导出。

## 12. 待用户提供的业务输入

- 软件研制任务书相关的历史问题汇总，可只包含检查项对应关系、问题标题、描述和整改建议；
- 对第一阶段 16 个检查项问题模板的逐项业务确认。
