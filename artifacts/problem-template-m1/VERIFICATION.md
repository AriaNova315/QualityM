# 问题模板优化里程碑 1 验收记录

日期：2026-09-01

## 实现范围

- 新审核实例初始为“未检查、零问题”，只冻结创建时可用的候选问题模板。
- 不符合结论支持一次选择多个候选问题；也可创建自定义问题，服务端在同一事务中同步结论。
- 带星检查项的问题固定为“严重”；非星检查项只允许“轻微、一般”。规则由纯领域模块统一校验，覆盖审核问题、模板新增/修改、复制、恢复和批量导入。
- 星号在审核页和阶段导出的问题序号后显示；普通模板编辑接口不能单独修改星标。
- 模板整改建议与实际整改措施分开显示和保存。
- 系统建议的关闭/验证信息保留为待确认值；填写实际整改措施、实际关闭日期、验证日期和验证结论后才允许确认关闭。
- 审核问题可通过显式确认保存为全局问题模板，只复制可复用的问题内容，不复制责任人、项目日期、实际整改和验证事实。
- 每个检查项最多新增或重新启用 4 条问题模板；零条仅提示覆盖警告并允许自定义；历史超过 4 条的数据不删除，但禁止继续增加。
- 页面诊断显示中文名称、具体问题标题和处理办法，不直接暴露英文诊断代码。
- 阶段工作簿中未检查项不再被导出为“不适用”；待确认的建议值带有明确文字标识。

## 数据兼容

## 启动回归修复

首次实现曾机械地把种子 JSON 中 361 个兼容用默认标记改为 `false`，但没有升级 `seed_version=2.0.1`，导致已有数据库在启动时正确报出 `Seed version 2.0.1 content changed`。该改动不是新业务规则所必需：007 迁移已经清除数据库默认标记，种子导入器也会忽略该兼容字段。

修复后种子文件恢复为 `2.0.1` 的原始不可变内容，SHA-256 为 `9ae0de102416349778af0173864b562ff055ee0c9bb03b2aa58723b6d049eb9b`；新增自动化测试锁定“版本号 + 内容指纹”契约。使用真实 `qualitym.db` 的副本执行完整应用生命周期，健康接口返回 `200`，数据库完整性为 `ok`，数据库中的启用默认标记仍为 0。无需修改或重建用户数据库。
